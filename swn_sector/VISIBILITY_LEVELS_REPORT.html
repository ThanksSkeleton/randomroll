1. The implemented model

Visibility is no longer one ordered enum.

Every selectable entity carries four booleans under Visibility: BasicScan, DetailedScan, PoliticsScan, and DeepPoliticsScan. “Invisible” means all four are false. Separately, every entity has string fields with the same four names under Intelligence, plus InfoboxSummary and GM.

Basic is the rootB---
BasicDetailedPoliticsDeep

Once Basic is on, Detailed is independently on/off. Politics has three states: off, Politics on, or Politics + Deep on. That produces six visible combinations plus the invisible state. The dependency rules are:

Detailed ⇒ BasicPolitics ⇒ BasicDeep ⇒ Politics ⇒ Basic

The UI’s six buttons are therefore not six mutually exclusive “levels.” They are one hide/show control, two science choices, and three politics choices. Several are highlighted at the same time to describe one combined state.

3. Each visibility flag: consumers and generated content

implicit state

Invisible · ----

  • Player maps and system views omit the entity because player inclusion is exactly BasicScan.
  • If an invisible selection survives long enough to reach the inspector, it displays RESTRICTED; switching to player preview also clears a hidden selection.
  • GM preview ignores visibility and continues to show and inspect it.

Generated state: all generated entities start here before the starting-world reveal. All POIs remain here after that reveal.

root visibility

Basic Scan · BasicScan

  • Controls whether an entity exists at all in player map/system views.
  • Unlocks the player inspector and portrait artwork.
  • Shows the Basic Scan section and a live “stock” summary based on structural fields.
  • Uses the procedural name until Politics is enabled.

Stored generated text: Intelligence.BasicScan = "-" for every entity. That field is not rendered by the inspector. Substantive Basic content is computed live; see the entity matrix below.

independent science branch

Detailed Scan · DetailedScan

  • Shows the Detailed Scan section and its stored editable text.
  • There is no generated Detailed Scan stock; physical HPOI details appear in Basic Scan.
  • Does not affect names, entity inclusion, or portraits.

Generated value: no entity receives this flag during generation. Stored Intelligence.DetailedScan is initialized to -, but the GM can edit it.

politics branch, stage 1

Politics Scan · PoliticsScan

  • Switches every player-facing entity name from ProceduralName to NiceName.
  • Where a secondary procedural label already exists, it remains visible beside/below the nice name.
  • Shows numeric and named technology level for inhabited planets and gates their symbolic technology rating.
  • A route’s own Politics flag controls whether its displayed endpoint names are nice or procedural.
  • Acts as the prerequisite for Deep Politics.

Generated value: enabled on starting-system objects, the ship, directly incident routes (Politics 1), and first-order neighbor objects/portals. Stored Intelligence.PoliticsScan is initialized to - and is not rendered or editable in the inspector. Entity types without Politics stock show -.

politics branch, stage 2

Deep Politics Scan · DeepPoliticsScan

  • Shows the Deep Politics section.
  • Requires Politics, which in turn requires Basic.
  • Displays - as its currently empty stock value plus stored editable Intelligence.DeepPoliticsScan.

Generated value: enabled only for the starting system’s system/star/objects and the ship. No entity type currently has substantive Deep stock; the tier remains available for upcoming political features.

not a visibility flag

GM Information

  • Visible only on the inspector’s GM tab in GM preview, irrespective of scan flags.
  • For inhabited planets, live stock shows generated World Tags.
  • For POIs, the stored GM field contains generated detail-table rolls.
  • The stored GM field is editable for every entity.

Generated stored text: - everywhere except POIs, whose GM text is one or more labeled rolled details.

6. Important consequences and remaining mismatches

Basic and Politics stored text are dead in the inspector implementation gap

Intelligence.BasicScan and Intelligence.PoliticsScan exist in the schema, edits layer, and validation, but the inspector renders only live stock for those sections. There is no editor or output for their stored strings. Detailed and Deep do render and edit their stored strings.

Route disclosure is intentionally route-local

A route’s Politics flag—not either endpoint system’s flag—controls whether destination and endpoint names are nice or procedural. This avoids cross-entity visibility lookups and leaves consistency under GM control.

Symbolic ratings now follow the revised tiers

Habitability remains visible at Basic, population requires Detailed, and technology requires Politics. Deep Politics has no live stock facts and remains open for upcoming political features.

First-order neighbor portals get broader knowledge than their routes

Every portal physically located in a neighboring system receives Basic + Politics, even when its associated route is not incident to the starting system and remains invisible. This is valid under the spec, but it creates known portal records whose route is not drawn/known.

GM scan preview is “all tiers,” not “what the player sees”

In GM preview the scan panel shows all four scan sections regardless of the entity’s flags. This is useful for editing, but the section list does not itself communicate which sections a player actually receives; that status lives in the separate visibility buttons.

Descriptions can expose exact visual facts at Basic

Basic visibility renders entity glyphs and portraits based on actual type/category, and the inspector’s portrait alt description names the category. That may be intended, but it means the boundary is broader than the Basic text block alone.

Audit scope and interpretation

This report treats the current TypeScript implementation as authoritative. Current specs were used to understand intent, but archived enum-era documents were not treated as current behavior. “Generated value” distinguishes serialized Intelligence strings from the live stock strings computed by the React inspector.

No application code was changed for this audit. The only deliverable is this standalone HTML file.
